# How Focus Pot works

A guided tour for anyone who wants to read, learn from or change the code: what lives where, how each feature works, and five small exercises. For installing and using the app, see the [README](../README.md).

## Why the taskbar and not a top "notch"?

A notch at the top-center is a macOS/iPhone idea; on Windows that's where tabs and title bars live. Windows 11 centers the taskbar icons, which leaves the **left end of the taskbar empty**, so Focus Pot docks there and never covers your work.

It picks its spot automatically (**Settings → Dock**):

| Your taskbar | Where the pill goes |
| --- | --- |
| Bottom, icons centered (Windows 11 default) | **On** the taskbar, at the left end |
| Icons left-aligned / Windows 10 / auto-hide / side taskbar | A small pill floating **just above** the taskbar |

**Why this split?**
- Each file does one job.
- `src-tauri/` may touch Windows; `src/` may only draw and ask. The page can call exactly the commands in `commands.rs`, nothing else (no file system, shell or HTTP access).
- `api.js` and `commands.rs` are the two ends of the bridge.
- `layout.css` never names a colour or radius directly. It uses tokens like `--surface`, `--primary` and `--r-card`, and each theme file fills those in. That's why a whole new look is one CSS file (plus, for glass, one small script).

### Where your data lives

| What | Where |
| --- | --- |
| Tasks, links, settings (incl. theme), today's count, screenshot categories | `%APPDATA%\FocusPot\state.json` |
| Screenshots | `Pictures\FocusPot\<yyyy-mm-dd>\<hh-mm-ss>.png` |

`FOCUSPOT_DATA_DIR` and `FOCUSPOT_PICTURES_DIR` (environment variables) point Focus Pot at other folders, e.g. for a portable copy or tests.

## How each feature works

**Placement and click-through.**
- The window is one big transparent, frameless, always-on-top box pinned to the bottom-left of the screen.
- `dock.rs` compares the monitor's full area with its work area; the difference is the taskbar. It tells the page where to draw the pill and the panel (in CSS pixels) and sizes the window in physical pixels, so it lines up exactly at any display scaling.
- The page sends the rectangles that are "solid" (the pill, the open panel, an open menu). A background thread checks the cursor every 30 ms and flips the window's `WS_EX_TRANSPARENT` style, so everywhere else clicks fall through to the apps underneath.
- The window stays `WS_EX_LAYERED` all the time and only `WS_EX_TRANSPARENT` changes: toggling `LAYERED` makes Windows redraw the whole window, which used to show up as a blink.

**Tap to open, tap outside to close.**
- Tapping the timer opens the panel; tapping it again closes it.
- The page can't see clicks that fall through to other apps, so the same 30 ms thread watches the mouse buttons: a press outside every solid rectangle is sent to the page as `outside-click`, and the panel closes (unless it's pinned).

**Staying above the taskbar (no blink).**
- The taskbar is "always on top" too: clicking it lifts it above Focus Pot, which hid the pill until the next re-raise.
- `dock.rs` subscribes to two Windows events (`SetWinEventHook`): "a window came to the front" and "the stacking order changed". The moment either fires, it checks whether the taskbar is above us and, only then, lifts us back. Measured: back on top before the change can even be observed. The 30 ms thread re-checks as a backup.

**Themes.**
- `<html data-ui="windows|material|mac">` picks which theme file's tokens apply.
- Each theme has its own icon set stored in a `<template>`. `Shell.applyTheme` copies the active one into the live sprite, and every `<svg><use href="#i-play"/></svg>` picks up the new symbol automatically.
- The Material colours are computed **in CSS** from your accent: Material's colour space defines "tone" as CIE L*, the same L used by CSS `lch()`. So `lch(from var(--seed) 80 48 h)` is "your accent's hue at tone 80", which is Material's dark-theme *primary*.

**Liquid Glass (macOS theme).** It follows Apple's rules for the material (HIG Materials, WWDC25 *Meet Liquid Glass*, the 2026 refinements):
- **Glass only in the functional layer.** The pill, the panel it presents and the dropdown menus are glass. Everything *on* the panel (cards, rows, chips, buttons, the tab picker) is a plain translucent fill: "never glass on glass".
- **Seeing through it.** A web page can blur its own content (`backdrop-filter`) but not the desktop behind its window. So `dock::snapshot_behind` takes a small picture of what's behind the panel. `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` hides Focus Pot from that one capture only (it stays on screen), and the picture is shrunk to a third and blurred in Rust, which is far cheaper than a CSS blur. `glass.js` paints it inside the panel, lined up with the screen.
- **The material.** A tint, a soft light from above, a darkened edge for depth, and a specular rim (a conic gradient) that is brightest where light hits the top-left corner. Near the rounded edge an SVG `feDisplacementMap` bends the picture outwards, like the rim of a thick lens.
- **Legible over anything.** Apple measured secondary text on glass as low as 2.3 : 1, and larger glass is meant to grow more opaque. So each picture is measured: `glass.js` finds the brightest 10 % of what's behind the panel and darkens the tint just enough for the secondary text to keep **4.5 : 1**. Over a dark desktop the glass stays clear; over a white web page it frosts up.
- **Clear ↔ Tinted.** Like the slider Apple added in iOS 27, Settings → Theme → Glass sets how tinted the glass is at least. Legibility still wins: the measurement can only add tint.
- **Tint means "important".** The accent is a background only on Start (and the add button on Tasks); elsewhere it marks status: the selected tab, the timer ring, a ticked task, a switch that is on. Icons stay monochrome.
- **Concentric corners.** An inner corner is the outer one minus the gap: panel 36 → tab picker 26 (10 in) → its thumb 23 (3 in) → cards 20 (16 in).
- **Quiet at rest, alive on touch.** The panel grows out of the pill on a spring while its lens "materializes" (bends strongly, then settles) instead of fading. The tab thumb moves like a drop: the leading edge races ahead and the trailing edge catches up. The pill swells slightly when pressed and light gathers where you pressed; switch knobs and slider thumbs turn into small glass lenses while you hold them.
- **Windows' own settings.** Transparency effects off → the glass gets frostier (more tint and blur) and Settings says why. Contrast themes / more contrast → stronger text and visible edges on every control. Animation effects off → no springs or swelling; things fade or slide.
- Pictures are taken only in this theme: when the panel opens and every 2.5 s while it stays open. They live in memory only and are never saved.

**Media.**
- Windows lists every app's media session through `GlobalSystemMediaTransportControlsSessionManager`, the API behind the Quick Settings media card. `media.rs` calls it directly through the `windows` crate (WinRT), so there's no helper process.
- Volume and mute go through Core Audio (`IAudioEndpointVolume`); "Other players" sends real media keys.
- Album art is cropped square once per track. Its average colour tints the Material card; the macOS card blurs the art itself into a glow.
- **Polling:** every second while the Media tab is open; every 2.5 s otherwise (only while music in the pill is on); never when both are off.

**Focus timer.**
- The timer stores the moment the phase ends and recomputes from `Date.now()` every 500 ms, so it never drifts.
- The dial and the pill's ring are SVG circles drawn with `stroke-dasharray`. In Material the arc and the track are separated by a small gap, like Material 3's progress indicators.
- Presets and steppers change the lengths instantly; a running timer is never touched.

**Tasks, links, screenshots.**
- Only one task can be active (★), and finishing a task clears it.
- Links open only `http(s)://`.
- Captures hide Focus Pot for 250 ms. Deleting a screenshot goes to the Recycle Bin.
- Every path the page sends is checked: the backend only touches image files inside `Pictures\FocusPot`.

## Build it yourself

Requirements: Windows 10 or 11, [Rust](https://rustup.rs), the Visual Studio **"Desktop development with C++"** Build Tools, and Node.js 18+.

```bash
npm install
npm run build
```

This creates the installer in `src-tauri\target\release\bundle\nsis\`. For quick runs while you work, `start.bat` builds once with `cargo build --release` and then just starts the app.

The icons and installer art are drawn by `npm run icon`; the three icon sets and the fonts are refreshed by `npm run assets`.

## Learn this codebase

### Suggested reading order

1. **`src/index.html`.** The shape of the UI: `#trigger` (timer face + music face), `#flyout` (tabs + pager + footer).
2. **`src/styles/layout.css` with `theme-windows.css` open next to it.** Components only use tokens; the theme fills them in.
3. **`theme-material.css`.** A whole colour scheme generated from one colour, using `lch(from …)`.
4. **`theme-mac.css`, then `src/js/glass.js`, then `snapshot_behind` in `dock.rs`.** How a web page fakes real glass.
5. **`src/js/api.js` next to `src-tauri/src/commands.rs`.** The bridge, from both sides.
6. **`src-tauri/src/dock.rs`.** Placement maths, click-through, outside clicks and the stacking hooks.
7. **`src/js/shell.js`.** Tap to open, pinning, the sliding tabs and theme switching.
8. **`src/js/timer.js`.** A drift-free timer and an SVG progress dial.
9. **`src-tauri/src/media.rs`, then `src/js/media.js`.** WinRT from Rust, and a small update-in-place UI component.

### 5 small exercises

1. **Change the Material seed colour.** In `theme-material.css`, set `--seed: #3d8bfd;` instead of `var(--accent-base)` and watch the whole scheme regenerate. Then try changing the tone numbers (e.g. primary 80 → 70).
2. **Tune the glass.** In `config.rs`, change `GLASS_BLUR` (18 → 8 for clearer glass, 28 for frostier). In `glass.js`, change `TARGET` (the contrast the tint must protect, 4.5) or `BEND` (how strongly the edge bends), and watch how the panel adapts over a white page and over a dark wallpaper.
3. **Add a shortcut.**
   - Add `Code::KeyR` to `KEYS` in `shortcuts.rs`, and in the handler emit an event: `app.emit("reset-timer", ())`.
   - Add `'reset-timer'` to `EVENT_CHANNELS` in `api.js`.
   - Expose `reset` from `Timer` and listen for it in `app.js`.
   - List it in the Settings tab.
4. **Add a preset.** Add `{ name: 'Sprint', focus: 10, rest: 2 }` to `PRESETS` in `timer.js`. The preset row is a 4-column grid in `layout.css` (`.presets`); make it fit 5.
5. **Long break every 4 sessions.**
   - Add `longBreakMin` to `sanitize_settings` in `store.rs` and to the defaults in `store.js`.
   - Add a stepper for it on the Focus tab.
   - In `Timer.finishPhase()`, use it when `Store.data.stats.pomos % 4 === 0`.
